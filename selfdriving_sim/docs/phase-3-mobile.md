# فاز ۳ — داشبورد موبایل و Mock Inference

## دامنه و تنظیمات تأییدشده

- گوشی هدف: **اندروید، Chrome به‌روز**؛ CSS مبتنی بر Tailwind 4 به Chrome 111 یا جدیدتر نیاز دارد.
- دسترسی امن به دوربین: **HTTPS با ngrok**.
- نرخ هدف ارسال: **۲۰ فرمان در ثانیه** با `setInterval(..., 50)`.
- ظاهر: **Tailwind محلی**، فونت وزیرمتن محلی، راست‌به‌چپ، مناسب حالت عمودی و افقی.
- صفحه: `/dashboard/`، نمایشگر PC: `/`.

مدل این فاز **Mock** است: تصویر ضبط می‌شود ولی در تصمیم فرمان نقشی ندارد. هیچ مدل Hugging Face یا TensorFlow.js در این فاز دانلود یا اجرا نشده است. تبدیل مدل و پیش‌پردازش واقعی مربوط به فاز ۴ است. اعمال فرمان‌های WebSocket به حرکت خودرو مربوط به فاز ۵ است؛ `applyControls` در صحنهٔ فعلی فقط فرمان را در کنسول PC لاگ می‌کند.

## اجرای گوشی با ngrok

تمام دستورهای پروژه را از پوشهٔ `selfdriving_sim/` اجرا کنید. وابستگی‌های Python و پایگاه داده باید طبق README اصلی آماده باشند.

### ۱. Redis و سرور Django

```bash
redis-cli ping
# PONG

source .venv/bin/activate
python manage.py migrate
python manage.py runserver 0.0.0.0:8000
```

Redis را روی loopback نگه دارید؛ نیازی به انتشار پورت ۶۳۷۹ یا ساخت تونل برای آن نیست.

### ۲. تونل HTTPS

ngrok را روی همان PC نصب و در محیط محلی خودتان راه‌اندازی کنید. در ترمینال دوم:

```bash
ngrok http 8000
```

آدرس HTTPS نشان‌داده‌شده توسط ngrok را کپی کنید و `/dashboard/` را به انتهای آن اضافه کنید. آدرس را **مستقیماً در Chrome گوشی** باز کنید، نه مرورگر داخلی پیام‌رسان یا iframe. اگر صفحهٔ هشدار اولیهٔ ngrok ظاهر شد، ابتدا آن را تأیید کنید.

هیچ توکن یا رمز ngrok نباید داخل کد، کامیت، لاگ، PR یا تصویر ارسالی قرار بگیرد. فایل `.env` از قبل در Git نادیده گرفته می‌شود.

### ۳. نمایشگر PC و دسترسی دوربین

1. روی PC صفحهٔ `http://localhost:8000/` را باز کنید و کنسول مرورگر را در دسترس داشته باشید.
2. گوشی را روی استند، روبه‌روی مانیتور و بدون حرکت قرار دهید.
3. در Chrome گوشی، مجوز دوربین را تأیید کنید. صدا درخواست نمی‌شود.
4. تصویر زنده باید ظاهر شود و وضعیت ارتباط به **متصل** و سبز تغییر کند.
5. **شروع خودران** را بزنید؛ پس از حدود یک ثانیه نرخ ارسال نزدیک ۲۰ FPS می‌شود.
6. چرخش قربیلک فرمان، درصد گاز، وضعیت ترمز و راهنماها را بررسی کنید. راهنمای چپ از نظر مکانی در چپ پنل است، حتی با صفحهٔ RTL.
7. **توقف** را بزنید؛ FPS صفر می‌شود و ارسال دوره‌ای قطع می‌شود.

آدرس WebSocket از `location.host` ساخته می‌شود: برای صفحهٔ HTTPS از `wss://…/ws/control/` و برای HTTP محلی از `ws://…/ws/control/` استفاده می‌شود. کد گوشی هیچ آدرس localhost یا IP ثابتی برای سرور ندارد.

> سرعت HUD، km/h خودروی صفحهٔ PC است و از `/ws/render/` به گوشی می‌رسد. تا وقتی صفحهٔ شبیه‌ساز باز و وصل نباشد، مقدار «—» می‌ماند. این عدد از گاز Mock ساخته نمی‌شود. FPS نرخ `send` موفق مرورگر است، نه نرخ فریم دوربین یا تأیید دریافت سرور. فرمان‌های Mock هنوز خودرو را حرکت نمی‌دهند؛ آن کار فاز ۵ است.

## ظاهر و رفتار

- `video#camera-feed` کل viewport را با `object-fit: cover` می‌پوشاند؛ تصویر آینه‌ای نمی‌شود.
- راه‌اندازی دوربین با `facingMode: { ideal: "environment" }` و عرض مطلوب ۱۲۸۰ انجام می‌شود. انتخاب دوربین عقب ترجیحی است؛ اگر دستگاه آن را ارائه ندهد، مرورگر می‌تواند دوربین دیگری برگرداند.
- `canvas#process-canvas` مخفی و دقیقاً ۲۰۰×۶۶ است. فقط `drawImage` انجام می‌شود؛ خروجی به تنسور تبدیل نمی‌شود.
- قربیلک فرمان با مقدار steering می‌چرخد. راهنماها و پدال‌ها با کلاس `active` و درصد عددی به‌روز می‌شوند. کنترل‌ها نشانگر **فرمان ارسالی** هستند، نه بازخورد واقعی خودرو یا پدال قابل لمس.
- هر سه ثانیه کلاس راهنما در چرخهٔ خاموش، چپ، خاموش، راست تغییر می‌کند. steering و throttle سینوسی و قابل تکرارند؛ brake هنگام اجرای Mock صفر است.
- شروع تا آماده بودن دوربین و باز شدن WebSocket غیرفعال می‌ماند. کلیک دوباره حلقهٔ موازی نمی‌سازد.
- توقف دستی، علاوه بر پاک کردن interval، در صورت باز بودن و خلوت بودن سوکت فقط یک درخواست `{steering: 0, throttle: 0, brake: 1, turn_signal: 0}` می‌فرستد.
- قطع دوربین، خطای ثبت تصویر، پاسخ خطای سرور، قطع ارتباط یا انباشته شدن بیش از ۱۰۲۴ بایت در صف سوکت، ارسال را متوقف می‌کند.
- تلاش مجدد WebSocket با فاصله‌های ۰٫۵، ۱، ۲، ۴، ۸ و سپس حداکثر ۱۵ ثانیه انجام می‌شود. پس از ۱۰ تلاش، دکمهٔ **اتصال مجدد** نمایش داده می‌شود. هر handshake پس از ۱۰ ثانیه بی‌پاسخ ماندن بسته می‌شود.
- بازگشت ارتباط **هرگز ارسال را خودکار شروع نمی‌کند**. کاربر دوباره شروع را می‌زند.
- با پنهان شدن صفحه یا `pagehide`، حلقه و تایمرها پاک می‌شوند، اتصال بسته و تمام trackهای دوربین آزاد می‌شوند. هنگام بازگشت، دوربین و اتصال دوباره آماده می‌شوند، ولی ارسال دستی می‌ماند.
- دارایی‌ها محلی‌اند؛ تصویر ویدئو ذخیره یا روی شبکه ارسال نمی‌شود. فقط چهار عدد کنترل به سرور می‌روند.
- در نمایشگرهای بسیار کوتاه، پنل قابل اسکرول عمودی است تا دکمه‌ها حذف نشوند؛ ویدئو همچنان تمام‌صفحه می‌ماند.

### محدودیت ایمنی

ارسال فرمان توقف **best effort و بدون acknowledgment** است؛ اگر ارتباط قطع باشد، رسیدن آن تضمین نمی‌شود. این پیاده‌سازی نباید به‌عنوان توقف اضطراری قابل اتکا تلقی شود. timeout/watchdog در سمت شبیه‌ساز و اعمال واقعی ترمز باید در فاز ۵ طراحی و تست شوند. این پروژه فقط شبیه‌ساز است، نه کنترل وسیلهٔ نقلیهٔ واقعی.

## لاگ سرور

هر فرمان معتبر در ترمینال Django/Daphne لاگ می‌شود؛ نمونه:

```text
INFO simulation.consumers: Control /ws/control/ steering=0.250 throttle=0.600 brake=0.000 turn_signal=1
```

این لاگ فقط چهار مقدار اعتبارسنجی و محدودشده را دارد؛ هیچ تصویر یا payload اضافی لاگ نمی‌شود. برای خاموش کردن لاگ ۲۰ هرتزی:

```bash
SIMULATION_CONTROL_LOG_LEVEL=WARNING python manage.py runserver 0.0.0.0:8000
```

## ساخت CSS محلی

خروجی کامپایل‌شدهٔ CSS و یک فایل WOFF2 در مخزن موجودند؛ برای اجرای معمول سرور نیازی به Node نیست. برای تغییر ظاهر، Node 20 یا جدیدتر لازم است:

```bash
npm ci
npm run build:css
# برای توسعهٔ محلی در ترمینال جدا:
npm run watch:css
```

فایل منبع: `client/styles/dashboard.css`؛ فایل قابل سرو: `client/static/client/css/dashboard.css`. بعد از تغییر کلاس‌های template یا JavaScript، CSS را دوباره بسازید و خروجی را هم کامیت کنید. نسخه‌ها و وابستگی‌ها در `package-lock.json` قفل شده‌اند. اطلاعات و مجوز وزیرمتن در `client/static/client/fonts/` قرار دارد.

## تست خودکار

```bash
source .venv/bin/activate
python manage.py check
pytest
npm ci
npm run build:css
npm test
npm audit
```

- تست‌های Python: مسیر، template، دارایی‌های محلی، هدر امنیتی، لاگ مقادیر اعتبارسنجی‌شده، پروتکل و relay از کنترل به رندر.
- تست Redis علاوه بر group round-trip، ۲۰ فرمان با فاصلهٔ ۵۰ میلی‌ثانیه و سپس فرمان توقف را از هر دو consumer عبور می‌دهد. در نبود Redis این تست‌ها با دلیل روشن skip می‌شوند.
- تست‌های Node: مرزهای Mock، WSS، backoff، FPS واقعی ارسال، خطاهای دوربین، حفاظت در برابر پاسخ دیرهنگام مجوز، شروع/توقف تکراری، reconnect، backpressure، شاخص‌های HUD و پاک‌سازی منابع.

### Chromium با دوربین آزمایشی

```bash
# Redis باید در حال اجرا باشد. مرورگر تست را یک بار نصب کنید:
npx playwright install --with-deps chromium
npm run test:browser
```

Playwright سرور توسعه را اجرا می‌کند یا سرور موجود روی پورت ۸۰۰۰ را به کار می‌گیرد. محیط مجازی Python باید فعال باشد. برای تست سروری که خودتان اجرا کرده‌اید:

```bash
DASHBOARD_TEST_URL=http://127.0.0.1:8000 npm run test:browser
```

`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` برای استفاده از Chromium نصب‌شدهٔ موجود نیز پشتیبانی می‌شود. تست مرورگر با **دوربین مصنوعی Chromium** انجام می‌شود؛ این به معنی تأیید سنسور واقعی گوشی نیست. موارد پوشش‌داده‌شده شامل مسیر کامل تصویر→Mock→Django→Redis→WebSocket رندر، خطاهای مجوز، توقف، reconnect، lifecycle و چیدمان عمودی/افقی است.

### چک‌لیست پذیرش روی سخت‌افزار واقعی

این موارد باید توسط صاحب گوشی و روی تونل واقعی بررسی شوند:

- [ ] `/dashboard/` در Chrome اندروید با HTTPS باز شود و درخواست مجوز نشان داده شود.
- [ ] بعد از تأیید، تصویر **دوربین عقب** همان گوشی زنده و درست جهت‌گیری‌شده باشد.
- [ ] وضعیت WebSocket سبز شود و HTTPS→WSS بدون خطای mixed-content کار کند.
- [ ] با شروع، نرخ نزدیک ۲۰ FPS، فرمان، گاز و راهنماها به‌روز شوند.
- [ ] کنسول Django فرمان‌های دریافتی و کنسول PC فرمان‌های `applyControls` را نشان دهند.
- [ ] با توقف، تعداد پیام‌ها ثابت بماند و دکمهٔ شروع دوباره فعال شود.
- [ ] قطع شبکه و برگشت آن، ارسال را بدون کلیک مجدد شروع نکند.
- [ ] قفل گوشی/تعویض تب، دوربین و ارسال را آزاد کند؛ بازگشت نیازمند شروع دستی باشد.

## عیب‌یابی و امنیت توسعه

| نشانه | اقدام |
|---|---|
| پیام «اتصال امن لازم است» | به‌جای IP محلی با HTTP، آدرس HTTPS ngrok را باز کنید. روش flags در این تنظیمات انتخاب نشده است. |
| مجوز دوربین رد شده | در تنظیمات سایت Chrome، دوربین را مجاز و دکمهٔ فعال‌سازی دوباره را بزنید. |
| دوربین مشغول است | برنامه‌های دوربین/تماس تصویری را ببندید و دوباره تلاش کنید. |
| تصویر هست ولی WebSocket قرمز است | Redis، ترمینال Django، فعال بودن ngrok و مسیر `/ws/control/` را بررسی کنید؛ از Django ASGI/Daphne استفاده کنید، نه WSGI. |
| صفحه بدون استایل است | در توسعه از `runserver` استفاده کنید. Daphne مستقل staticfiles را سرو نمی‌کند؛ برای استقرار `collectstatic` و وب‌سرور لازم است. |
| خودرو با Mock حرکت نمی‌کند | در فاز ۳ عمدی است؛ صحنه فرمان را لاگ می‌کند و اعمال حرکت در فاز ۵ انجام می‌شود. |
| iframe تصویر نمی‌دهد | لینک HTTPS را مستقیماً در Chrome باز کنید؛ مجوز camera در iframe به سیاست میزبان هم وابسته است. |

`SECURE_CROSS_ORIGIN_OPENER_POLICY = 'same-origin-allow-popups'` حفظ شده است. برای پیش‌نمایش تعبیه‌شدهٔ توسعه می‌توان `DJANGO_ALLOW_IFRAME_PREVIEW=1` داد؛ این گزینه فقط همراه `DEBUG` اثر دارد و محافظ X-Frame-Options را حذف می‌کند. در اجرای معمول و ngrok فعالش نکنید.

تنظیمات فعلی پروژه توسعه‌ای هستند: `DEBUG=True`، `ALLOWED_HOSTS=['*']` و WebSocket بدون احراز هویت است. URL تونل را عمومی نکنید، از آن فقط برای تست کوتاه استفاده کنید و بعد از تست تونل را ببندید. امنیت استقرار عمومی و احراز هویت کنترل‌کننده در دامنهٔ این فاز نیست.
