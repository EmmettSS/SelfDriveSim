# راهنمای عیب‌یابی SelfDriveSim

شش مشکل رایج و راه‌حل مرحله‌به‌مرحله. قبل از هر چیز: `python manage.py check` را بزنید و
مطمئن شوید `redis-cli ping` جواب `PONG` می‌دهد.

## ۱. Redis وصل نمی‌شود

**نشانه‌ها:** سرور بالا می‌آید اما فرمان از گوشی به صفحه نمی‌رسد؛ در لاگ Daphne خطای
`Error 111 connecting to 127.0.0.1:6379. Connection refused.`؛ در pytest دو تست با
`no Redis server reachable` رد می‌شوند.

**راه‌حل:**

```bash
redis-cli ping                       # باید PONG بدهد
sudo systemctl status redis-server   # وضعیت سرویس
sudo systemctl enable --now redis-server
```

- اگر Redis جای دیگری اجرا می‌شود: `REDIS_HOST` و `REDIS_PORT` را به‌عنوان متغیر محیطی یا
  در `.env` ست کنید.
- بدون Redis می‌توانید **فقط برای آزمایش تک‌کاربره** سرور را بالا بیاورید: در `settings.py`
  موقتاً `BACKEND` را `channels.layers.InMemoryChannelLayer` بگذارید (چند پروسه Daphne
  دیگر کار نمی‌کند — فقط برای توسعه).
- اجرای داکری: `docker run -d -p 6379:6379 redis:7` و سپس `REDIS_HOST=127.0.0.1`.
- توجه: `run.sh` و `run.bat` قبل از اجرا وجود Redis را بررسی می‌کنند و با پیام راهنما
  متوقف می‌شوند.

## ۲. دوربین روی گوشی کار نمی‌کند (HTTPS)

**نشانه‌ها:** پیام «اجازهٔ دوربین داده نشد» یا خطای `NotAllowedError`؛ یا اصلاً درخواست
مجوز ظاهر نمی‌شود.

**علت اصلی:** `getUserMedia` فقط در **Context امن** کار می‌کند — `https://` یا
`http://localhost`. آدرس `http://192.168.x.x:8000` روی گوشی عمداً دوربین نمی‌دهد.

**راه‌حل (ساده‌ترین مسیر، ngrok):**

```bash
ngrok http 8000
```

- آدرس `https://…ngrok-free.app/dashboard/` را در Chrome گوشی باز کنید (همین آدرس به‌صورت
  `wss://` برای WebSocket هم استفاده می‌شود).
- پنجرهٔ مجوز را **Allow** بزنید؛ اگر روزی Allow را Reject کردید: منوی 🔒 کنار آدرس ←
  Permissions ← Camera ← Allow، و صفحه را رفرش کنید.
- iOS Safari: مجوزها در Settings › Safari › Camera هم کنترل می‌شوند؛ صفحه باید مستقیم در
  مرورگر باز شود نه داخل یک اپ دیگر (Telegram/Instagram درون‌مرورگری مجوز می‌دهد).
- گزینهٔ بدون اینترنت: یک(reverse proxy) محلی با گواهی self-signed + نصب گواهی روی گوشی،
  یا Chrome flag `unsafely-treat-insecure-origin-as-secure` (فقط برای تست).
- مطمئن شوید دوربین **عقب** فعال است؛ داشبورد `facingMode: environment` را درخواست می‌کند.

## ۳. WebSocket قطع می‌شود

**نشانه‌ها:** در HUD صحنه «قطع (n)» قرمز؛ در داشبورد گوشی «قطع/تلاش مجدد n».

**رفتار مورد انتظار:** قطعی با backoff نمایی (۰.۵، ۱، ۲، ۴، ۸ … سقف ۱۵ ثانیه) حداکثر ۱۰ بار
تلاش می‌شود؛ بعد باید صفحه را دوباره بارگذاری کنید.

**بررسی‌ها:**

- سرور واقعاً Daphne/runserver است؟ (هر دو ASGI هستند و WebSocket می‌دهند.)
- ngrok رایگان بین هر start یک صفحهٔ بین‌راهی نمایش می‌دهد؛ اولین بازدید را در مرورگر
  تأیید کنید.
- اگر پشت proxy هستید، timeout خواندن proxy را بالا ببرید (مثلاً nginx
  `proxy_read_timeout 3600s`).
- فایروال/پورت ۸۰۰۰ از سمت PC باز است؟ `curl http://<IP-PC>:8000/health/` روی خود PC.
- `ALLOWED_HOSTS = ["*"]` در حالت توسعه هندشیک همهٔ originها را می‌پذیرد؛ در استقرار واقعی
  آن را محدود کنید وگرنه رفتار origin-check متفاوت خواهد بود.
- صفحهٔ PC را بعد از خواب/ساسپند مانیتور دوباره بارگذاری کنید؛ تب‌های پس‌زمینه rAF را
  متوقف می‌کنند (خودرو با آخرین فرمان کهنه توقف می‌کند، چون فرمان بعد از ۰.۵ ثانیه منقضی است).

## ۴. مدل بارگذاری نمی‌شود

**نشانه‌ها:** نشانگر داشبورد روی `MOCK MODE` می‌ماند و پیام «مدل بارگذاری نشد؛ شروع خودران
فرمان‌های Mock می‌فرستد» ظاهر می‌شود؛ کنسول گوشی `[Model] Load failed` را نشان می‌دهد.

**بررسی‌ها:**

1. فایل‌ها سرو می‌شوند؟
   `curl -o /dev/null -w "%{http_code}" http://<host>/static/client/models/dave2/model.json`
   باید `200` بدهد (همچنین `group1-shard1of2.bin` و `group1-shard2of2.bin`).
2. اگر `404` گرفتید: `python manage.py collectstatic --noinput` و پیکربندی وب‌سرور
   استاتیک‌ها را ببینید (`selfdriving_sim/README.md` → Serving the static files).
3. کش خراب مرورگر: Settings › Privacy › Clear cache، یا رفرش با cache-bypass.
4. WebGL/حافظه: Chrome گوشی را ببندید و دوباره باز کنید؛ در گوشی‌های کم‌حافظه TF.js ممکن
   است OOM بدهد — پیام خطا در کنسول remote debugging دیده می‌شود.
5. اگر عمداً مدل را حذف کرده‌اید، Mock جایگزین درست رفتار است؛ فرمان‌های Mock
   `steering = 0.65·sin(0.7t)` می‌فرستند و برای تست صحنه‌اند، نه رانندگی واقعی.

## ۵. خودرو خارج از جاده / می‌زند به دیوار

**نشانه‌ها:** شمارندهٔ «دیوار» در HUD بالا می‌رود؛ فلاش نارنجی؛ خودرو روی `|x| = 9` می‌ماند؛
یا در تست حلقه‌بسته خودرو از لاین خارج می‌شود.

**بررسی‌ها (به ترتیب احتمال):**

1. **قرارگیری گوشی:** کل مانیتور در کادر دوربین باشد، بدون زاویهٔ تند؛ صفحهٔ مانیتور
   روشن و بدون براقیت/انعکاس نور؛ فوکوس دوربین روی صفحه قفل شود (ضربهٔ نگه‌داشتن روی
   نقطه فوکوس).
2. **علامت فرمان:** اگر خودرو **برعکسِ** انحنای جاده می‌پیچد، قرارداد علامت مدل با صحنه
   فرق دارد — در `simulation/static/simulation/js/scene.js` ثابت `STEERING_SIGN` را از
   `1` به `-1` تغییر دهید (یک خط، همان‌جا مستند است).
3. **روشنایی صحنه:** مانیتور خیلی کم‌نور ⇒ نویز؛ روشنایی و کنتراست سیستم را بالا ببرید.
4. **سرعت:** سرعت ۲۰ m/s با نرخ ۲۰Hz فرمان، بین دو فرمان ~۱ متر جابه‌جایی دارد؛ اگر مدل
   دیر واکنش نشان می‌دهد، کاهش `MAX_SPEED_MS` راه تشخیصی خوبی است که انحنا را قابل رانندگی می‌کند.
5. **عملکرد عمدی:** دیوار نامرئی برای تنبیه خروج از جاده طراحی شده است — برخورد با آن
   سرعت را می‌ساید و هشدار «مسیر را عوض کن» را به گوشی می‌فرستد؛ اگر فقط جریمهٔ بصری
   می‌خواهید، در `updateEgoPhysics` بخش clamp را خنثی کنید.

## ۶. تأخیر زیاد (>200ms)

**نشانه‌ها:** واکنش خودرو به انحنای جاده کند است؛ فرمان مدل روی داشبورد با تصویر
همگام نیست.

**تجزیهٔ زنجیره تأخیر:** دوربین (۳۰–۶۰ms) + استنتاج (۱۰–۳۰ms) + ارسال/رله
(LAN: ۲–۵ms، ngrok: ۳۰–۱۵۰ms) + رندر صحنه (≤۱۶ms) ⇒ مجموع سالم روی LAN حدود ۶۰–۱۲۰ms
و روی ngrok حدود ۱۰۰–۲۵۰ms.

**کاهش:**

- **tunnel:** ناحیهٔ نزدیک ngrok را انتخاب کنید (`ngrok http 8000 --region=eu`)؛ جایگزین:
  Tailscale/WISE یا WSS مستقیم روی LAN با گواهی محلی — کمترین تأخیر.
- **Wi-Fi:** باند ۵GHz، فاصله کم از اکسس‌پوینت؛ هات‌اسپات موبایل نباشد (چون همان گوشی
  دوربین است و رادیو را با دوربین شلوغ می‌کند).
- **دوربین:** در صورت پشتیبانی، فریم‌ریت پایین‌تر/اکسپوژر کوتاه‌تر تأخیر صف دوربین را کم
  می‌کند؛ برنامه‌های پس‌زمینه گوشی را ببندید.
- **استنتاج:** مدل float16 است و سبق؛ GPU هوشمندِ مرورگر فعال باشد (Chrome
  `chrome://gpu` WebGL Hardware accelerated).
- **رندر:** مانیتور ۶۰Hz کافی است؛ مرورگر PC را بدون تب‌های سنگین دیگر اجرا کنید.
- **سنجش:** عدد «پیام بر ثانیه» داشبورد باید ~۲۰ باشد؛ افت بزرگ ⇒ گلوگاه شبکه/صف ارسال
  است نه مدل (`socket.bufferedAmount` محافظ تعبیه‌شده دارد).

## هنوز حل نشد؟

- لاگ سرور: `SIMULATION_CONTROL_LOG_LEVEL=WARNING` برای ساکت‌کردن جریان ۲۰Hz و دیدن
  خطاهای دیگر.
- خروجی `pytest` و `npm test` هر دو باید سبز باشند؛ اگر یکی قرمز است، اول همان را درست
  کنید.
- سند معماری (`docs/architecture.md`) جدول کامل پیام‌ها را دارد تا مسیر خطا را دنبال کنید.
